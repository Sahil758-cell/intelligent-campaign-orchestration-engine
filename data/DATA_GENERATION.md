# Synthetic Data Generation

## Overview

The synthetic data (`synthetic_events.json`, `product_catalogue.json`) was generated by `data/generate_data.py` using a fixed random seed (`random.seed(42)`) for reproducibility.

## Temporal Integrity

To ensure no browse event appears after an order for the same product in the same session, browse events use `offset_minutes` to place them before the order timestamp. The `make_browse_event()` function always generates events with `TODAY - offset` to ensure temporal ordering.

## Recipient Clustering

Several customers have ordered for the same named recipient across multiple occasions:

- **CUST006:** "Mom" on Mother's Day + "Mom" birthday (December)
- **CUST007:** "Wife" on Valentine's Day + "Wife" anniversary
- **CUST009:** "Dad" on birthday + "Dad" on Father's Day
- **CUST016:** "Mom" on Mother's Day + "Mom" birthday (October)

This ensures the occasion detection engine's recipient clustering logic is exercised.

## Cold-Start Customers (CUST046–050)

These customers have exactly 1–2 browse events and no order history. They are used to test the send-time optimiser's cold-start fallback (segment-level defaults).

## Realism Choices

1. **Timezones on every event:** All timestamps include UTC offset matching the customer's home timezone, not UTC-normalised — this is how real Shopify/WATI data arrives.
2. **AOV distribution:** Order totals are `price × qty × noise(0.9–1.1)` — realistic because customers sometimes add gift wrapping or delivery tips.
3. **WhatsApp read rates:** Generated as Bernoulli(0.7) per event — matches industry WhatsApp business message read rates (~65–75%).
4. **Opted-out customers:** Four customers (CUST005, CUST012, CUST035, CUST044) have a WhatsApp opted-out event — used to verify consent management.
